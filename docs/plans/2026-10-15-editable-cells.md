# Editable Code Cells Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every visible code cell on a browser page (a page with `kernelspec`,
not `layout: scrolly`, not `runtime: colab`) becomes a CodeMirror 6 editor that
students can edit and run on the page. It runs on the JupyterLite kernel MyST
already ships. `runtime: colab` pages show read-only code plus a "Do this
tutorial in Colab" banner.

**Architecture:** A document-stage MyST plugin (`plugins/cells/cells.mjs`)
replaces code blocks with anywidget panels and adds one hidden page-runtime
widget that carries a manifest of all cells. In the browser, a shared
`PageRuntime` (`plugins/cells/src/runtime.mjs`) boots thebe-lite once per page,
builds a thebe notebook from the manifest and runs cells with notebook
semantics. Each panel's output lives in light DOM, slotted into the panel's
shadow root. Earlier unfinished exercises run their reference solution via the
existing kernel-side fallback cell. The explicitly run cell carries a
`# nma-no-fallback` marker that switches the fallback off.

**Tech Stack:** mystmd 1.11.0 (thebe-core/thebe-lite 0.5.0, Pyodide 0.27),
CodeMirror 6, esbuild, Node 22 (`node --test`), Python 3 + pytest, Playwright
(Python) for the browser smoke test, GitHub Actions.

**Spec:** `docs/plans/2026-10-15-editable-cells-design.md`. Read it first,
because its code sketches are the reference for every task below. Its appendix
(pre-rendered outputs / `--execute`) is **out of scope**.

## Global Constraints

- `requirements.txt`: `mystmd==1.11.0` (was `mystmd>=1.3`). The panels depend on its bundled thebe 0.5.0 API.
- Node 22 (`.nvmrc`). `node --test tests/js/*.test.mjs` must pass **without** `npm install` (pure modules only in tests).
- CodeMirror pins in `plugins/cells/package.json` (exact versions): `@codemirror/view` 6.43.14, `@codemirror/state` 6.7.6, `@codemirror/commands` 6.11.1, `@codemirror/language` 6.13.1, `@codemirror/autocomplete` 6.20.3, `@codemirror/lang-python` 6.2.1, `@lezer/highlight` 1.2.5, `esbuild` 0.28.2 (devDependency).
- `plugins/cells/dist/*.mjs` are generated, committed and start with `// GENERATED by npm run build in plugins/cells. Do not edit.`
- Frontmatter key `runtime`, values exactly `browser` (default) or `colab`.
- Fallback opt-out marker string: `nma-no-fallback` (Python `NO_FALLBACK_MARKER`, JS `NO_FALLBACK_MARKER`).
- Unfinished-exercise regex: `^[ \t]*raise NotImplementedError` (multiline), same as `nma_solutions.py`.
- Exact UI copy:
  - Exercise label: `Exercise · fill in, then run`
  - Other labels: `Python`, `Python · code hidden`, `Output`
  - Buttons: `▶ Run`, `Reset`, `Show code` / `Hide code`, `Restart`
  - Booting: `Starting Python… the first run takes about 10 seconds`
  - Running: `Running…`
  - Done: `[<count>] ✓`
  - Error: `[<count>] ✗ <ename>`
  - Output-only hint: `Run to see output`
  - Stale: `Edited · run to update`
- Colab banner: admonition kind `important`, title `Do this tutorial in Colab`, text `This tutorial needs more computing power than your browser has, so its code can’t run on this page. ` + link `Open in Colab` + ` or ` + link `Kaggle` + ` to edit and run it.`
- CSS tokens as listed in the spec's "Styling" table. Theme follows `html.dark` / `html.light`.
- Power button hidden site-wide: `.myst-jp-nb-toolbar-power { display: none !important; }` in `_static/custom.css`. Keep `project.jupyter.lite: true` (MyST only emits the thebe assets with it).
- Scrolly pages, pages without `kernelspec` and generated notebooks must not change.
- No asset URL may be root-absolute in browser code. Derive from `import.meta.url` (forks deploy under `github.io/<repo>/`).

## Review Focus

1. **Hydration double-mount** (panels render twice while the page loads): exactly one output element per panel, edits kept. Tests: `register()` replacing an element in Task 4, panel count in Task 6 e2e.
2. **Run clicked on several panels quickly, or during boot:** runs are serialized, each earlier cell runs once, one kernel boots. Test: concurrent `run()` in Task 4.
3. **Navigating to another page while the kernel is booting or busy:** the old runtime is disposed, and the new page gets a fresh kernel. Tests: `pageRuntime()` path change in Task 4, navigation in Task 6 e2e.
4. **Explicitly running a partly edited exercise that still has the `raise` line:** shows `NotImplementedError`, never the solution. Tests: marker in Task 2, `withNoFallback` target-only in Task 4, e2e in Task 6.
5. **Site deployed under a subpath:** thebe scripts and bundles resolve relative to the bundle URL. Test: `thebeScriptUrls()` in Task 3.

  - `export async function ensureThebeLoaded(bundleUrl: string)`: resolves when `window.thebeCore?.api && window.thebeLite`. Otherwise injects the two `<script>` tags from `thebeScriptUrls(bundleUrl)` (once) and waits up to 30 s.

- Behaviour as in the spec's `PageRuntime` sketch, plus:
  - `boot()` attaches every element in `this.outs` once the notebook exists.
  - `restart()` calls `ready.session.kernel.restart()`, clears `ran`, sets `this.queue = Promise.resolve()` and emits `{kernel:'ready', restarted:true}`.
  - `window` and `location` are read inside functions only, never at module top level, so tests can set globals.

  Tests (assert on `log` entries of kind `exec`):
  - `run(3, 'f()')` executes 0, 1, 2 with their original code (no marker), then 3 with `withNoFallback('f()')`, in that order.
  - Edits are used: with `rt.edits[1] = 'a = 2'`, `run(3, …)` executes cell 1 as `'a = 2'`.
